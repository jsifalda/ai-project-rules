# Cut `/ship-pr` from ~20-30 tool calls to 3

- Restructured `ship-pr` from 6 phases into 4, and folded each phase into one batched bash
  block. The hot path is now three tool calls: preflight, then commit+push, then open the PR.
- Measured first. Every shell command in the skill costs about 2-3 seconds in total. The real
  cost was the number of agent round-trips, because the old document listed commands one by one
  and an agent ran each as its own call.
- Dropped the full `git diff HEAD` read on the hot path. The agent that just made the changes
  already knows the type, the scope, and the why. A delegating run still reads `--stat`, because
  its subagents authored the diff and their summaries can miss a file. An unexplained tree still
  reads the diff. This does not weaken the secret scan, which tests path globs and file size and
  never read diff content.
- Removed the `gh auth status` / `glab auth status` network call, at the user's decision. A new
  failure-mode row carries the recovery command, because a failed PR creation now happens after
  the commit and the push, and a second run cannot repair a clean tree.
- Made the upstream slug lookup lazy. Only the fork fallback needs it, and that path is rare.
- Fixed several defects found while reviewing, some of them older than this change: an
  in-progress rebase, revert, or sequencer operation could go undetected; an empty default
  branch let a commit land on the default branch; `--assignee` on the create could fail the
  whole PR; a jq call could kill the block after the MR existed; quoted and prefixed porcelain
  paths failed to stage; a closed PR's URL could be reported as a fresh one.
- Updated `better-plan` to match the new phase numbers and the new behavior it describes.
