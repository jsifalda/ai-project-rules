# code-review-full: make the spec pass produce a verifiable ledger

- The acceptance-criteria pass now writes `$RUN/spec-ledger.json`, one row per criterion with a
  status, an anchor and a traced chain. Stage 6 verifies every `implemented` row against the
  branch bytes and demotes the rows that fail. Stage 9 publishes the rows as a table.
- An anti-false-clear protocol runs before any `implemented`, and a criteria invariant forbids a
  blanket pass sentence in place of the rows.
- The report renderer draws the new criteria section and omits it when the spec lens did not run.
- Why: on a recorded run the spec pass declared every criterion implemented. Nothing verified that
  claim and no per-criterion record reached the report, so a false all-clear could ship.
- The examples use placeholder ticket keys and file names, so no internal identifier is published.
